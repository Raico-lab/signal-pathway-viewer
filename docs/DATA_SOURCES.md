# DB 構築のための情報源

遺伝子間の制御関係 DB を作るときに、どの情報をどこから集めるかのまとめ。対象は TOR 経路に限らず全遺伝子。
1 つのデータベースで全部はそろわない。特に「活性化か抑制か」という作用の向きと閾値は、どのデータベースにも十分には載っていない。

## 情報の種類ごとのおすすめ

| 必要な情報 | おすすめの情報源 | 注意点 |
|---|---|---|
| 遺伝子名・Systematic 名・機能説明 | **SGD**（Saccharomyces Genome Database）。一括で取るなら SGD の **YeastMine** | 酵母の遺伝子名の標準なので、ここに合わせておくと名前の照合で困らない |
| 複合体の構成（TORC1、TORC2、PKA、SAGA など） | **EBI Complex Portal**、または SGD の複合体情報 | 構成要素は文献によって多少違う |
| リン酸化などの酵素と基質の関係 | **BioGRID**（リン酸化部位の情報も含む） | 向きはわかるが、活性化か抑制かはわからない。全遺伝子を対象にするなら一括で取り込み、`effect` は `none`（表示のみ）から始める |
| 転写因子と標的遺伝子（GLN3 → MEP2 など） | **YEASTRACT+** | 正の制御か負の制御かの根拠も付いている。全転写因子分を一括で取れる。第 2 段階の予測では発現データと直接突き合わせるので、特に重要 |
| 経路全体の骨格と、活性化・抑制の判定 | 総説論文から手作業で拾う | 下の「進め方」を参照 |

骨格づくりに使える総説の例（TOR 経路の場合。他の経路も同様に経路ごとの総説を使う）:

- Loewith & Hall (2011) *Genetics* 「Target of rapamycin (TOR) in nutrient signaling and growth control」
- González & Hall (2017) *EMBO J* 「Nutrient sensing and TOR signaling in yeast and mammals」

## 進め方

全遺伝子の関係すべてに、人が作用の向きや閾値を付けることはできない。そこで「一括で取り込む層」と「手作業で精査する層」に分ける。

1. **全遺伝子を登録する**: SGD（YeastMine）から全遺伝子の遺伝子名・Systematic 名・機能説明を一括で取り込む。
2. **関係を一括で取り込む**:
   - YEASTRACT+ から全転写因子の標的遺伝子を取り込む（`interaction_type` は `transcription`）。正負の根拠があれば `effect` に `activate` / `inhibit` を入れ、根拠がなければ **`none` を明記する**（空欄だと `transcription` は自動で「活性化」扱いになるため）。
   - BioGRID からリン酸化などの酵素と基質の関係を取り込む（`effect` は `none` から始める）。
3. **重要な経路を精査する**: 研究で注目する経路（TOR など）は、総説をもとに活性化か抑制か（`effect` 列）と根拠の文献（`evidence` 列）を手作業で付ける。精査済みかどうかが分かるよう、`evidence` に明記する。
4. **閾値は必要な所だけ**: 閾値は、シミュレーションや予測に使う経路にだけ付ければよい。

BioGRID のうち、遺伝学的相互作用（約 60 万行）と物理的相互作用（約 28 万行）は取り込んでいない。
どちらも「どちらがどちらを制御するか」を表すものではなく、入れると関係が多すぎて図が読めなくなるため。
また、BioGRID の MITAB 形式には修飾の種類（リン酸化・ユビキチン化など）が含まれないため、`enzymatic` 型は種類を区別していない。
区別が必要になったら、BioGRID の TAB3 形式（Modification 列がある）で取り直す。

## 酵素-基質の関係の「種類」と「作用」を補う

BioGRID から取り込んだ酵素-基質の関係（約 6,000 組）は、何の修飾か（種類）も、活性化か抑制か（作用）も不明のまま登録している。種類はまとめて補えるが、作用は文献に頼る部分が残る。

### 修飾の種類：BioGRID の TAB3 形式（取り込み済み）

いま使っている BioGRID の MITAB 形式には修飾の種類がないが、同じ BioGRID の **TAB3 形式**（`BIOGRID-ORGANISM-Saccharomyces_cerevisiae_S288c-<版>.tab3.txt`）には「Modification」欄があり、酵素活性の実験（Biochemical Activity）の行に Phosphorylation・Dephosphorylation・Ubiquitination・Acetylation などが入っている（取り込む前に、実際のファイルで中身と埋まっている行数を確認する）。

- 補えるもの: 取り込み済みの組の大部分の「種類」
- 同じ版の同じデータなので照合しやすい。`raw_data/BIOGRID-ORGANISM-LATEST/` に置いてある
- 結果（2026-10-01）: 取り込み済みの 6,031 組すべてで修飾の種類が判明した。注記（Qualifications）に活性化・抑制の語を含むのは 56 行だけで、その多くは反応そのものの調節（「Mcm10 で促進される」など）なので、作用の向きの手がかりにはならなかった
- 酵母のリン酸化部位をまとめた PhosphoGRID も、現在は BioGRID に統合されている

### 出典の食い違い

取り込み（`tools/import_sources.py`）は、同じ組が複数の出典にあるとき片方を捨てずに根拠欄へ両方を残す。出典によって作用が食い違う組には根拠欄に「⚠ 出典で作用が食い違う」と書き、取り込まなかった矢印とあわせて `docs/source_conflicts.tsv` に一覧を出す（取り込みのたびに作り直す）。2026-10-02 時点で 8 件（KEGG の経路図どうしの食い違い 5、KEGG と YEASTRACT+ 1、精査済みと公開データ 1、作用する遺伝子を決められなかった矢印 1）。

破壊株データでの向きの推定の効き目（`tools/evaluate_sign_inference.py`、転写因子の破壊株は 5 組の交差検証。2026-10-02）: 推定を使わないとき 10 位以内 9.1%（転写因子 24.6%・それ以外 1.5%）に対し、作用不明を埋めると転写因子の順位の中央値が 37 → 29 とわずかに良くなるが、10 位以内の割合はどのやり方（食い違いを作用不明・反転、推定の基準 1.7／1.3／1.15 倍）でも 8.6〜11.7% で、評価する株数（197）から見て差ははっきりしない。転写因子以外（シグナル伝達の遺伝子）は良くならない。そのため DB では、作用不明を埋めるだけにして、記録と食い違う関係は記録のままにしている。

既知の注意点（未対応）: KEGG の「リン酸化で促進」は、図の上の矢印で機能としては抑制のことがある（PHO85→PHO4 など、111 本）。KEGG の「間接的な作用（indirect effect）」は直接の関係として登録している（62 組）。

### 作用の向き（信頼度の高い順。KEGG は取り込み済み）

| 情報源 | 内容 | 注意点 |
|---|---|---|
| **KEGG PATHWAY（酵母 sce）** | 経路図の関係に activation / inhibition / phosphorylation などの区別がある（KGML 形式）。MAPK（sce04011）、細胞周期（sce04111）、オートファジー（sce04138）、長寿経路（sce04213、TOR・PKA を含む）など | 対象は主要経路に限られる。大量取得は利用条件を確認する（学術目的の REST API は無料） |
| **総説・原著論文**（手作業） | 注目する経路（TOR・PKA・SNF1 など）の確かな向き | 最も確実。取り込み済みの関係の `evidence` にある PMID を手がかりに確認できる |
| **キナーゼ・ホスファターゼ欠損株のリン酸化プロテオミクス**（Bodenmiller et al. 2010 *Sci Signal* など） | 酵素を欠損させたときの基質側の変化から向きを推定 | 間接的な推定。「推定」と区別して登録する |
| **リン酸化部位の機能スコア**（Viéitez et al. 2022 *Nat Biotechnol*） | 酵母のリン酸化部位ごとの機能への影響 | 「活性化か抑制か」までは直接わからないことが多い |

SIGNOR・OmniPath・PhosphoSitePlus など、作用の向き付きの主要データベースはヒト中心で、酵母にはほとんど使えない。

### 進め方

1. BioGRID TAB3 で種類を補う（済み）
2. KEGG の酵母経路で主要経路の向きを補う（済み）（`evidence` に「KEGG sce04011」のように記録）
3. 注目する経路は文献で精査する（`sample_data/` の精査済みデータを拡張）
4. 必要になったら、プロテオミクスからの推定を「推定」と区別できる形で追加する

作用の向きは状況によって変わることも多く、全部を埋める必要はない。アプリは作用不明の関係を表示だけに使うので、分かっているものから順に増やせばよい。

## 閾値について

閾値（`threshold`）と強度（`weight`）は仮の値のままでよい。アプリの可視化タブで矢印をクリックして調整しながら、観察結果に合う値を探していく。

## 記録のルール

データベースの情報は研究の進展で変わるため、`evidence` 列に **情報源と取得日** を残す。

例: `YEASTRACT+ (2026-10取得), DNA binding evidence` / `Loewith & Hall 2011 Genetics`

CSV の列の詳細は [README.md](../README.md) の「CSV フォーマット」を参照。
